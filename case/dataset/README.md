# Данные

## Источник

Генератор `sqltr.gen` (запуск: `python case/dataset/generate.py ...` или `python -m sqltr build-dataset ...`). Открытые корпуса (BIRD Mini-Dev, TPC-H) подключаются вторым этапом и в первую версию набора не входят.

- **Хранилище.** Синтетическая розница в схеме `retail`: покупатели, товары, магазины, заказы, позиции, оплаты, остатки (`sqltr/warehouse.py`).
- **Скрипты.** 14 шаблонов сценариев: витрина продаж, помесячная выручка по категориям, последний заказ покупателя, когорты, остатки с обновлением статуса, сверка оплат, теги товаров, RFM, календарь с нулями, рейтинг магазинов, промокоды, партиционированный факт, коды лояльности, контакты покупателей.
- **Парные рендеры.** Каждый шаблон с параметрами рендерится в двух диалектах с одинаковой семантикой (`sqltr/gen/render.py`, по методу на каждую точку расхождения диалектов). Рендер на исходном диалекте - вход примера. Рендер на целевом - эталонный перевод для тестов метрики.
- **Эталон.** Хеши выходных таблиц исходного скрипта на исходном движке на каждом состоянии данных. Эталонные переводы метрике не нужны.

## Состояния данных

| Состояние | Что проверяет |
|---|---|
| s1 | Обычные данные |
| s2 | NULL в нулевых колонках, ничьи в суммах и времени, кириллица в именах и городах |
| s3 | Граничные даты (конец месяца, 29 февраля, переход года, полночь), большие числа |
| s4 | Крошечные таблицы, оплаты и остатки пустые |

## Одно распределение

Все разделы строит один генератор с одинаковыми параметрами. Train строится из публичного сида `20261101`, public и private - из секретных сидов оператора (`operator/seeds.json`, вне git). Семейства public и private, совпавшие с семействами train, пересэмплируются, так что разделы не пересекаются и взяты из одного распределения.

## Семейства

Семейство - шаблон с фиксированными параметрами. Его стилевые варианты (перефразы: `::` или `CAST`, `date_add` или `INTERVAL`, префикс каталога, опции хранения, комментарии) и оба направления всегда попадают в один раздел, поэтому перефраз не утекает из train в private. Пространство семейств - больше 600 для 14 шаблонов; train берет 250.

## Размеры и обоснование

| Split | Семейств | Примеров (оба направления) | Почему столько |
|---|---|---|---|
| train | 250 | 500 | Покрывает все 14 шаблонов и 30+ классов расхождений, хватает на подвыборки исследователей |
| public | 100 | 200 | При pass rate около 0.5 стандартная ошибка ≈ 0.035; различаем кандидатов с разницей от ~0.07 |
| private | 100 | 200 | Та же точность для финального сравнения с baseline |

Обоснование: метрика детерминирована, шум только выборочный; замер примера на PostgreSQL занимает около 0.06 с, на Trino замеряется на ЧП1 и может уменьшить public. Решение фиксируется в [ADR 0003](../../docs/adr/0003-dataset-split.md).

## Формат

UTF-8 JSONL в формате `Example` арены, одна запись на строку:

```json
{"id": "tr-gp2trino-daily_sales-1a2b3c4d-v0", "input": "{\"direction\": \"gp2trino\", \"script\": \"...\"}", "reference": "{\"target\": \"trino\", \"states\": [\"s1\", \"s2\", \"s3\", \"s4\"], \"outputs\": {\"wrk.daily_sales_30d\": {\"hashes\": [\"...\"], \"rows\": [57, 55, 49, 3]}}}"}
```

`reference` решателю не передается. Public и private хранятся у оценщика вне доступа исследователя; их id непрозрачны (хеш), чтобы не выдавать шаблон. Рядом лежит `meta.jsonl` (шаблон, семейство, классы расхождений) - для train он доступен исследователю, для public и private - только оператору.
