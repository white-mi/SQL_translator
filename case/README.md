# Кейс: перевод SQL-скриптов между диалектами

Оформлен по `cases/template` арены; копируется в `cases/sqltr` ее рабочей копии.

## Задача

- Вход (`example.input`): JSON-строка `{"direction": "gp2trino" | "trino2gp", "script": "<скрипт>"}`.
- Ответ: текст переведенного скрипта, `{"answer": "..."}` в stdout решателя.
- Разрешенные материалы решателя: train (скрипты, эталонные хеши, статистика ошибок), документация диалектов, библиотеки образа решателя (SQLGlot 30.27.0).
- Решатель работает без сети (`network=none` по контракту runner арены), к движкам не обращается. Фикстуры оценки, public и private ему недоступны.

## Разрешенные изменения

Исследователь меняет код решателя в `ways/<кандидат>/`: правила переписывания AST, обработку скрипта целиком, офлайн-самопроверку парсером целевого диалекта, а при модельном харнесе - промпт, отбор примеров и ремонт по ошибке разбора.

Зафиксировано до поиска: метрика и ее версия (`sqltr-metric-v1`), генератор и состояния данных, split, версии движков и арены, модель LLM, лимиты времени.

## Метрика

См. [metric/](metric). Направление: `maximize`. Скрипт получает 1, если все его выходные таблицы совпали с эталоном на всех четырех состояниях данных, иначе 0. Итог - среднее по примерам. Невалидный перевод получает 0, сбой инфраструктуры - явная ошибка проверки. Обоснование - в [ADR 0002](../docs/adr/0002-metric.md).
