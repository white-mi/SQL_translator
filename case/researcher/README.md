# Исследователь: образ, запуск и шлюз модели

Здесь все, что нужно агенту-исследователю арены: контейнер с Hermes, цикл запуска и шлюз, через который идут все вызовы модели. Решатель основной кампании модель не вызывает, так что это единственная статья расходов на модель. Почему устроено так - [ADR 0007](../../docs/adr/0007-models.md).

| Файл | Что делает |
|---|---|
| `gateway.py`, `gateway.haiku-5-5.json` | Шлюз модели: единственный процесс с ключом провайдера. Одна модель, лимит в долларах, в журнале только токены и стоимость |
| `Dockerfile` | Образ `sqltr-researcher:1`: Hermes на зафиксированном коммите и CLI арены. Контекст сборки - закрепленный архив арены, ее код в репозиторий не копируется |
| `hermes-config.yaml`, `run.py` | Настройки Hermes и цикл запуска: агент работает, пока журнал не скажет, что поиск окончен |
| `fake_model.py`, `rehearsal_script.json` | Фальшивый провайдер и сценарий исследователя для проверок без расходов |
| `rehearsal.sh` | Генеральная репетиция развертывания с фальшивым провайдером |
| `real_check.py` | Первые настоящие вызовы: несколько центов, отвечает на то, что фальшивый провайдер только предполагает |

## Что здесь неочевидно

- **Ключ есть только у шлюза.** Контейнер получает токен шлюза, а не ключ. Запрос уходит провайдеру байт в байт: любая правка сломала бы кэш промптов.
- **Лимит переживает перезапуск.** Потрачено - это сумма по журналу вызовов `model-usage.jsonl`. Стоимость записывается до того, как клиент увидит конец ответа, поэтому следующий вызов всегда видит предыдущий. Лимит можно превысить только на вызовы, которые уже идут (их не больше четырех). Лимит расходов в консоли провайдера остается последней страховкой.
- **Порог цены.** Haiku 5.5 считает запрос с промптом больше 100 000 токенов в пять раз дороже, и повышенную цену платит весь запрос, включая попадания в кэш. Поэтому Hermes считает, что окно модели - 100 000 токенов, и сжимает контекст на 75 000. Шлюз отмечает такие вызовы полем `long_prompt`.
- **Имя шлюза в контейнере - `api.anthropic.com`** (`docker --add-host`). Hermes выбирает правила протокола по имени хоста: с любым другим именем он считает маршрут сторонним ретранслятором и выбрасывает блоки thinking, а API просит возвращать их без изменений. Настоящий API при этом недоступен: брандмауэр разрешает только порт шлюза.
- **Токен шлюза начинается с `sk-ant-api`.** Токен другого вида Hermes может принять за OAuth и послать другие заголовки.
- **`python` в терминале агента - системный.** Терминал Hermes - login shell, он сбрасывает `PATH`, поэтому пакеты CLI арены стоят в системном Python образа, а у Hermes свое окружение. Там же стоит SQLGlot той же версии, что в образе кандидатов: исследователь может попробовать перевод, не тратя замер. Движков в контейнере нет, поэтому настоящую проверку дает только train-оценщик.
- **У исследователя нет интернета.** Он видит только оценщики и шлюз (`arena.sh firewall`, команда `researcher` применяет правила при каждом запуске). Поэтому все зависимости, включая SDK Anthropic, должны быть в образе: Hermes умеет доставлять пакеты на ходу, но здесь это не сработает.
- **После сжатия контекста** блоки thinking из сохраненного хвоста привязаны к уже измененной истории. На новых аккаунтах API отвечает на такой запрос ошибкой 400, Hermes убирает эти блоки и повторяет запрос. Одна такая ошибка на сжатие - норма, она не стоит денег.

## Генеральная репетиция

```bash
sudo bash case/researcher/rehearsal.sh results/researcher/rehearsal.json
```

Скрипт начинает с пустого каталога `/srv/sqltr-rehearsal` и своих сидов, проходит `layout`, `freeze`, `data`, `journal`, `workspace`, `start`, `readiness`, а затем запускает исследователя: заменен только провайдер в самом конце цепочки, Hermes, шлюз, брандмауэр, журнал, оценщик и runner настоящие. Денег не тратит. Рядом с настоящей кампанией не запускается: у оценщиков те же имена юнитов, и скрипт откажется работать, если журнал кампании уже есть.

Отчет проверяет три сценария: скриптованный исследователь делает настоящую работу и проверяет границы (A), сжатие контекста (B), достижение лимита (C). Последний отчет: [results/researcher/rehearsal-2026-11-08.json](../../results/researcher/rehearsal-2026-11-08.json).

Фальшивый провайдер отклоняет то, что отклонил бы настоящий Haiku 5.5: `budget_tokens`, параметры сэмплирования, запрос без последней реплики пользователя, блок thinking после правки истории. Это приближение: подпись у него - хеш предыдущей истории. Что на самом деле примет API, показывает только настоящий вызов.

## Первые настоящие вызовы

Ключ сохраняется в файл `$ROOT/secrets/model-api-key` (только сам ключ, владелец `arena`, права 0600) и в чат или в git не попадает. Лимит задает `MODEL_MAX_USD` в настройках оператора.

```bash
sudo bash case/deploy/arena.sh gateway
sudo python3 case/researcher/real_check.py --url http://172.30.0.1:8094 --token-file /srv/sqltr-arena/secrets/model-token
```

`real_check.py` отвечает на вопросы, на которые нельзя ответить без провайдера: принимает ли аккаунт заголовки Hermes, принимает ли API блоки thinking в цикле вызова инструмента и цикл без них, включена ли на аккаунте проверка правки истории, работает ли кэш промптов через шлюз.

## Другая модель

Для провайдера с протоколом OpenAI нужен свой файл настроек шлюза (`upstream`, `"auth": "bearer"`, `model`, цены), `MODEL_NAME` и `MODEL_GATEWAY_HOST` в настройках оператора и `--api-mode chat_completions` у `run.py`. В кампании модель одна: менять ее можно только до старта поиска. После смены модели повторяется `real_check.py`, а его проверки на блоки thinking относятся только к Anthropic.
