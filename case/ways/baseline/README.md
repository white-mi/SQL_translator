# Baseline

SQLGlot 30.27.0 `transpile` по операторам скрипта: `postgres → trino` для gp2trino и `trino → postgres` для trino2gp. Выбран стартовым кандидатом, потому что это стандартный открытый транспайлер, решает задачу одной функцией и задает понятную нижнюю точку для кривой эволюции.

- `solve.py` реализует контракт немодельного runner арены: JSON в stdin, `{"answer": ...}` в stdout.
- `sqlsplit.py` - копия разделителя операторов из пакета метрики: пакет кандидата должен быть самодостаточным, runner видит только `/candidate`.
- Решатель никогда не падает. Ошибка на операторе оставляет исходный оператор, любая другая ошибка - исходный скрипт. В арене падение кандидата на одном примере останавливает всю закрытую серию, поэтому это свойство сохраняется во всех потомках.

Где baseline ломается (train, см. `results/baseline/`):
- trino2gp: остается префикс каталога `iceberg.`, свойства Iceberg превращаются в `USING 'PARQUET'`, функции Trino без аналога в PostgreSQL (`split`, `format_datetime`, `to_hex(md5(...))`), MERGE вместо UPDATE ... FROM;
- gp2trino: оператор с `DISTRIBUTED BY` или опциями хранения Greenplum не разбирается и передается как есть, вместе со всеми `::`; временные таблицы, `age()`, `date_part`, `to_char`, DISTINCT ON остаются без перевода.
