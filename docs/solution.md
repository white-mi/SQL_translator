# Итоговое решение

Кампания `sqltr-c1` завершена (20.11): победитель и итоговое решение - **cand-30**. Результат против baseline: train 0.064 → 1.000, public 1.000, **private 0.060 → 1.000**, holdout 0.042 → 0.750 без семантических ошибок.

- **Идея:** перевод SQL-скрипта целиком устойчивым к отказам конвейером: предобработка исходника регулярными правилами → пооператорный transpile SQLGlot → постобработка выхода правилами целевого диалекта. Ни один оператор не падает: при неразобранной конструкции оператор уходит как есть.
- **Алгоритм** (`cand-30/solve.py`, 318 строк; снимок - в журнале, у оператора):
  1. Маскирование строк и комментариев, разбивка скрипта на операторы (sqlsplit).
  2. Предобработка входа: вырезание DDL-клауз, которые SQLGlot не разбирает (Greenplum `WITH (…)`, `DISTRIBUTED BY`, `PARTITION BY`; Trino `WITH (format/partitioning)`, префикс `iceberg.`), переписывание `CREATE TEMPORARY TABLE`, функций `split`/`format_datetime` с переводом шаблона даты.
  3. `sqlglot.transpile` по операторам с целевым диалектом; ошибка любого оператора - оператор без изменений.
  4. Постобработка выхода правилами (~30 правил в два слоя): арифметика дат (`DATE - N` ↔ `date_add`, разность дат ↔ `date_diff(day)`, `date_add(day, N, DATE)` ↔ `DATE + INTERVAL`, `CAST(DATE - INTERVAL AS DATE)` → `date_add`), функции (`md5`/`to_utf8`/`to_hex` в оба направления, `regexp_like` ↔ `~`, `json_extract_scalar` ↔ `->>`, `array_distinct`-агрегация ↔ `STRING_AGG(DISTINCT)`, `age` ↔ `date_diff`, `count_if` → `SUM(CASE)`, `if` → `CASE WHEN`, `unnest(generate_series)`-конвейеры), типы (`DOUBLE` → `NUMERIC`), синтаксис (`UPDATE … FROM` → `MERGE`, `LATERAL UNNEST` → `UNNEST`, `STRING_TO_ARRAY` → `SPLIT`, `JOIN … USING`).
- **Почему работает:** каждый класс расхождений закрыт семантически эквивалентной перезаписью; метрика проверяет не текст, а совпадение выходных таблиц на 4 состояниях данных - «почти правильные» перезаписи отсеиваются NULL-ами и пустыми таблицами.
- **Где ломается:** конструкции за пределами карты классов проходят без перевода (sql_error на целевом движке, 6 из 24 на holdout: вложенный `count_if(regexp_like(...))`, timestamptz в `GENERATE_SERIES`, новые формы интервалов, `JOIN USING`); резервный путь «оператор как есть» гарантирует, что решатель не падает (ADR 0008). Семантических ошибок нет: все исполненные скрипты дают верные таблицы.
- **Сложность и ключевые параметры:** один проход по операторам + линейные регулярные правила; решатель в контейнере ~120 с на 200 примеров private; SQLGlot 30.27.0, зафиксирован в образе `sqltr-runner:1`.
- **Как арена к нему пришла:** см. [evolution.md](evolution.md) - 30 предложений, каждый закрывает самый массовый класс ошибок по разбивке train; половина роста - первый шаг (устойчивость разбора); плато 1.0 достигнуто за 60% лимита.
- **Результат на private против baseline: 1.000 против 0.060 (×16.7)**; полный итог - в таблице [README](../README.md#итог-в-одной-таблице).
