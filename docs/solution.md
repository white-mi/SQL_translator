# Итоговое решение

Состояние на ЧП2 (20.11): кампания идет, лучшее решение - cand-14 (train 0.706). Итоговый вариант появится после финализации; здесь разбирается текущий лидер.

- **Идея:** перевод SQL-скрипта целиком устойчивым к отказам конвейером: предобработка исходника регулярными правилами → пооператорный transpile SQLGlot → постобработка выхода правилами целевого диалекта. Ни один оператор не падает: при неразобранной конструкции оператор уходит как есть.
- **Алгоритм** (`ways/cand-14/solve.py`, журнал хранит снимок каждого кандидата):
  1. Маскирование строк и комментариев, разбивка скрипта на операторы (sqlsplit).
  2. Предобработка входа: вырезание DDL-клауз, которые SQLGlot не разбирает (Greenplum `WITH (…)`, `DISTRIBUTED BY`, `PARTITION BY`; Trino `WITH (format/partitioning)`, префикс `iceberg.`), переписывание `CREATE TEMPORARY TABLE`, функций `split`/`format_datetime` с переводом шаблона даты.
  3. `sqlglot.transpile` по операторам с целевым диалектом; ошибка любого оператора - оператор без изменений.
  4. Постобработка выхода правилами: арифметика дат (`DATE - N` ↔ `date_add`, разность дат ↔ `date_diff(day)`, `date_add(day, N, DATE)` ↔ `DATE + INTERVAL`), функции (`md5`/`to_utf8`/`to_hex`, `regexp_like` ↔ `~`, `json_extract_scalar` ↔ `->>`, `array_distinct`-агрегация ↔ `STRING_AGG(DISTINCT)`, `age` ↔ `date_diff`), типы (`DOUBLE` → `NUMERIC`), синтаксис (`UPDATE … FROM` → `MERGE`, `LATERAL UNNEST` → `UNNEST`, `STRING_TO_ARRAY` → `SPLIT`).
- **Почему работает:** каждый класс расхождений диалектов закрыт семантически эквивалентной перезаписью; метрика проверяет не текст, а совпадение выходных таблиц на 4 состояниях данных - «почти правильные» перезаписи отсеиваются NULL-ами и пустыми таблицами.
- **Где ломается:** конструкции за пределами карты классов (нерегулярные шаблоны, неизвестные функции) проходят без перевода - на целевом движке это sql_error; резервный путь «оператор как есть» гарантирует, что решатель не падает (ADR 0008).
- **Сложность и ключевые параметры:** один проход по операторам + линейные регулярные правила; ~30 правил в два слоя (вход/выход); SQLGlot 30.27.0, зафиксирован в образе `sqltr-runner:1`.
- **Как арена к нему пришла:** см. [evolution.md](evolution.md) - 14 предложений, каждый закрывает самый массовый класс ошибок по разбивке train; половина роста - первый шаг (устойчивость разбора).
- **Результат на private против baseline:** будет после финализации (K=5, N=3); на train лидер 0.706 против 0.064 baseline.
