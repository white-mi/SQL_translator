# ADR-0008: Харнес переводит падение кандидата в нулевой ответ

- Статус: proposed (согласовать с руководителем вместе с остальными вопросами по арене)
- Дата: 2026-11-04

## Контекст
Комплектный runner арены при ненулевом коде выхода, таймауте или неверном JSON кандидата завершается ошибкой. Для private это значит: вся серия получает `failed`, без оценок и победителей, повторной отправки нет (проверено локальной приёмкой, сценарий A17 на комплектном runner). ADR-0005 требует от кандидата «никогда не падать», но кандидатов пишет исследовательский агент: одно необработанное исключение на скрипте, которого не было в train, сожжёт единственную private-попытку.

Падение программы-переводчика на конкретном скрипте - это плохой перевод этого скрипта, а не сбой измерения.

## Решение
- Регистрируем собственный харнес `sqltr-program` (образ `sqltr-runner:1`, `case/harness/main.py`) с тем же stdin/stdout-протоколом, что у комплектного runner арены. Контракт арены разрешает оператору сторонний харнес, зарегистрированный до кампании.
- Если `solve.py` упал, превысил 120 с, вывел не JSON или не `{"answer": str}`, харнес возвращает ответ-маркер `-- sqltr-harness-error: <вид>` с хвостом stderr.
- Метрика видит маркер и ставит 0 с `failure.kind = candidate_fault`; хвост stderr попадает в статистику train, поэтому исследователь видит причину падения.
- Ошибки самого задания (битый stdin от оценщика, модельный режим, build) по-прежнему завершают харнес с кодом 1: это инфраструктура, она должна падать громко.
- Внешний `ARENA_RUNNER_TIMEOUT` больше внутренних 120 с, чтобы таймаут кандидата оставался нулём, а не сбоем серии.

## Альтернативы
- Комплектный runner + дисциплина «никогда не падать» в коде кандидата: защищает только от ошибок, которые агент предусмотрел.
- Обёртка try/except внутри каждого кандидата: агент может её сломать или удалить; ревьюер должен это ловить вручную.

## Последствия
- Private-серия падает только из-за инфраструктуры (движки, Docker, метрика), а не из-за кода кандидата. Проверено приёмкой, в том числе на VM с Trino 8.11: A07 (train), A17 (private), A18 (сбой движка по-прежнему даёт `failed`).
- Семантика оценки не меняется: падение и раньше означало «нет верного перевода», теперь это явный 0 на примере вместо потери всей серии.
- Харнес фиксируется до кампании вместе с образом; его код - в репозитории, digest образа - в `preparation.md`.
