# ADR-0004: Движки - PostgreSQL 16 и Trino 483 на Iceberg

- Статус: accepted
- Дата: 2026-11-01

## Контекст
Нужно исполнять скрипты в диалекте Greenplum и в диалекте Trino на одной машине, воспроизводимо, с изоляцией и приемлемой скоростью.

## Решение
- Greenplum-диалект исполняется на PostgreSQL 16.4 после удаления физических опций хранения. Greenplum 7 основан на PostgreSQL 12, а различия, влияющие на результат запросов нашего класса, проверяются гейтом (MERGE).
- Trino 483 с коннектором Iceberg: JDBC-каталог в той же PostgreSQL и локальное хранилище на volume (без S3).
- База PostgreSQL создается с collation `C.UTF-8`: порядок строк совпадает с Trino, поэтому упорядоченные агрегаты и оконные функции дают одинаковый результат. Часовой пояс сессии - UTC.
- Apache Cloudberry (открытый форк Greenplum) - опционально, только для однократного расчета эталонов, в стенд кампании не входит.
- Права: в PostgreSQL - роль `sqltr_runner`; в Trino - файловые правила доступа (запись только в `wrk_*` и `sandbox_*`, чтение `retail_s*`).

## Альтернативы
- Cloudberry в стенде кампании: ближе к Greenplum, но тяжелее по ресурсам и не нужен для расчета результатов.
- Trino с MinIO и REST-каталогом: больше сервисов; оставлен как запасной вариант, если JDBC-каталог не заработает.
- DuckDB вместо Trino: другая семантика, кейс потерял бы смысл.

## Последствия
- Весь стенд поднимается одним `docker compose` на VM.
- Локальная разработка возможна без Trino: направление trino2gp проверяется на одном PostgreSQL.
- Нужно убедиться на стенде, что образ Trino содержит драйвер PostgreSQL для JDBC-каталога (по документации Trino, для PostgreSQL отдельный jar не нужен).
