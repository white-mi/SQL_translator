# Результаты

Все цифры ниже получены 8.11 на VM (2 vCPU, 8 ГБ RAM) исполнением на настоящих PostgreSQL 16.4 и Trino 483, если не сказано иное. Score - доля примеров, где все выходные таблицы совпали с эталоном на всех четырех состояниях данных.

Замеры до 11.11 сделаны метрикой `sqltr-metric-v1`. Версия `sqltr-metric-v2` отличается одним правилом: скрипт, который в PostgreSQL выходит за лимит временных файлов исполнителя (`temp_file_limit`, 1 ГБ), получает 0, как скрипт за лимитом памяти в Trino, а не роняет оценку как сбой инфраструктуры. Ни один ответ в этих замерах не упирался в лимит и не давал такого сбоя, поэтому цифры те же.

Выращенного решения пока нет: кампания не начиналась, а public и private еще не строились с секретными сидами. Поэтому здесь baseline, проверки стенда и проба подхода вне кампании.

## Проба подхода вне кампании

Субагент на Claude Haiku 5.5 в контейнере исследователя, 3 кандидата, только train. Это не итог проекта: журнал отдельный, кандидаты в кампанию не идут. Разбор и ограничения - в [docs/poc.md](../docs/poc.md), данные - в [poc/poc-2026-11-08.json](poc/poc-2026-11-08.json).

| Кандидат | Весь train (500) | gp2trino | trino2gp | Holdout (24) |
|---|---|---|---|---|
| baseline | 0.064 | 3/250 | 29/250 | 1/24 |
| c1 | 0.288 | 59/250 | 85/250 | 12/24 |
| c2 | 0.352 | 91/250 | 85/250 | 12/24 |
| c3 | **0.402** | 116/250 | 85/250 | **13/24** |

Работа агента заняла 12 минут и 28 вызовов модели, по ценам API это около $0.044, или $0.015 на кандидата. Это расчет по журналу субагента, а не счет.

## Почему baseline так низок

`sql_error` на 444 примерах из 468 провальных, гейт `MERGE` для Greenplum - на 21, несовпадение таблиц - на 3. Разбивка по шаблонам и классам расхождений - в [сводке](baseline/train/summary.json), разбор - в [docs/domain.md](../docs/domain.md).

## Архив

В `archive/2026-11-04-local/` лежат замеры 4.11, сделанные локально на одном PostgreSQL. Они оставлены как история и больше не используются:

- `baseline-gp2trino-offline.json` - офлайн-оценка gp2trino, когда Trino еще не было: верхняя граница 0.024 по числу переводов без конструкций Greenplum. Настоящий замер дал 0.012.
- `baseline-trino2gp-summary.json` - trino2gp на PostgreSQL с эталонами из парного рендера: 0.116, настоящий замер дал то же число.
- `holdout-baseline-trino2gp-summary.json` - holdout, только trino2gp: 0 из 12, настоящий замер дал то же число.

Сырые результаты по примерам лежат в `raw/` и в git не попадают. Любая цифра из сводок воспроизводится командами из [README](../README.md) и [stand/README.md](../stand/README.md).
